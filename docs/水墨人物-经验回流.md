# 经验回流草稿《常山赵子龙》· huashu-art-motion

> 水位线 2026-10-08 16:58（以下均为本轮新踩、尚未整合回 skill 的条目）

### [工程/Windows] render.py 在本机必须打的两个补丁，否则渲染直接超时
1. `socketserver.TCPServer` 默认 `request_queue_size=5`，Chromium 并发拉 20+ 个 js/woff 会 `ERR_CONNECTION_REFUSED` → 换成 `ThreadingTCPServer` 且 `request_queue_size=128`。
2. Chromium 会继承系统代理（本机如有代理软件开着，残留的代理规则会让本地请求也走代理），连 `127.0.0.1` 本地 http 服务也被拒 → launch 参数加 `--no-proxy-server`。
- 现象很有迷惑性：页面 `boot failed` / 超时 / 一堆 404，看着像缺资源，其实是这两条。已把补丁回写到 skill 的 `scripts/engine/render.py`。

### [工程/性能] 长片务必分段并行，别单行渲
`render.py` 有 `--from/--to`（秒，走完整 `index.html` 不进 solo）。把 25.4s 切成 4 段各起一个 chromium + ffmpeg 并行，8 核机器上 **50 分钟 → 14 分钟**。
- 关键：切点取「上一段末帧时刻 == 下一段首帧时刻」，例如 `--from 0 --to 6.9` / `--from 6.9 --to 13.3` / 13.3→19.7 / 19.7→25.4。跨切点的转场会被切成两半，但同一绝对时刻渲染完全确定，拼回来是无缝的。
- 收片：`ffmpeg -f concat -safe 0 -i list.txt -c copy -movflags +faststart 成片.mp4`（纯 remux，无损）。
- 查成片信息用 `ffmpeg -i`（ffprobe 不是必需品）。

### [流程] 交付前「独立审片」必须派一个没碰过源码的 agent，且要走两轮
只派一轮会漏：第一轮抓出长坂坡「没有阿斗、没有曹操兵、近乎死画面」、箕谷「两山刀切硬边」、首帧「枪杆横穿躯干」、以及 z7 误钤了上一幕的「汉水」印。
- 让它抽帧看图（不要只看稀疏总览，转场只有 0.34–0.46s），按严重/中等/分级，必须写「发生秒数 + 画面上具体是什么东西」。
- 第二轮再派一次（把上一轮问题列给它核对），让它只判「已改到位 / 仍有问题 / 新问题」，这样收敛快、结论可信。本轮结论：可交付。
- 快速自查用工程里现成的 `_solo_test.py <sceneId> ...`：批量调 `renderSolo` 并在 draw 抛错时打印，几秒钟就知道 8 幕有没有 JS 报错。

### [水墨/造型] 怀里抱的东西只画「一团白」读不出来，要补一个小头
`Z.rider` 的 `pouch` 原本是一枚白色椭圆＋红线十字。放到 1920 宽画面里就是一块白，看不出是阿斗。
- 改成放大到 19×21 的襁褓，再在上面加一颗小圆头（含胎发一点、眼睛一点），才是「怀抱幼主」。
- 同类教训：`hold` 分支的襁褓也一样，别只靠「留白」。

### [水墨/山石] `mountains(x0, x1)` 分两段画，内侧必留刀切垂直硬边
左右各画一次 `Z.mountains(c,g,0,760,…)` + `(1150,1920,…)`，中段空白 + 两端笔直裁切边，审片一眼就挑出来「像撕开的贴纸」。
- **错误改法**：拿一张平涂纸色（`#efe6d0`）的线性渐变矩形去压边。因为纸是有纹理的，平涂盖不住纹理边界，反而变成两块灰板，更丑。
- **正确改法**：远山用一条贯穿整幅的 `Z.mountains(c,g,-80,2000,…)` 不留裁切；近处两坡改用 `brush(...)` 粗笔触 + `tail: 0.86`，笔锋自带收尾，往谷心自然化开。

### [水墨/人物] 立姿举枪的起手角不能接近水平
`Z.hero` 里 `lerp(-0.15, -0.82, rl)`，rl=0（也就是开片第一帧）枪杆近水平，从颈胸高度笔直横穿白色躯干，读成「枪穿过人」。
- 改成 `lerp(-0.72, -0.96, rl)`：起手即 40° 左右斜举，整段都在「举枪亮相」的语义里。

### [版式] 每幕钤印必须统一位置，且印文别抄成上一幕的
- 全片统一钳在右下角（约 `x=1762, y=952`），落款挪到左下，视觉才整。
- 本片真出过错：`z7_dan.js` 里写的是 `Z.seal(c,260,950,'汉水',…)` —— 把上一幕的名字钤到了下一幕。定稿前 grep 一遍所有 `Z.seal(` 的印文和坐标是对的。

# 第二条片子《老将黄忠》（同一工程、换 `?film=`）

### [架构] 一部片子一个工程目录，靠 `?film=` + `SCENE_LIBS` 换片，别复制工程
- `eras_<名>.js` 里 `window.SCENE_LIBS = ['scenes/h_common.js']`，`scenes/index.js` 会按 `ERAS[].id` 同步 XHR 加载 `scenes/<id>.js` 并 eval 注册。
- 所以做第二部片只需：新段表 `eras_huangzhong.js` + 新笔法库 `h_common.js` + 八幕 `h1…h8`，**一点都不用碰** `z_common.js` / `z1…z8`。两个片子的共用笔法（`paper/wash/mountains/mist/flag/water/…`）都在 `h_common.js` 里重新 `sed` 改名（`zl_`→`hz_`）一份即可，互不污染。
- 渲染/验收一律带 `--film huangzhong`。

### [脚本] `_solo_test.py` 第一个参数当片子名，否则测新片报「没有这一段」
原来把 `?film=zilong` 写死了。改成 `FILM = sys.argv[1]`（限 `[a-z0-9_]`），后续参数是 scene id：`python _solo_test.py huangzhong h1_nanyang h2_changsha …`，批量调 `renderSolo` 并打印 draw 报错。

### [API] `U.rng(seed)` 返回的是**函数**，不是数字
写成 `const r = rng(88)()` 会直接 `TypeError: r is not a function`。正确：`const rr = rng(88)`，后面每次取值写 `rr()`。

### [CSS] 窄构图、竖持的弓不能用扁弧（初版弓像彩虹）
`Z.bow` 最初写成横着的一根扁弧（`moveTo(±96)` 中间鼓），出图就是一道彩虹。
- 中国弓是**竖向持握**：上下两条弓臂用一条 `quadraticCurveTo` 出弯（控制点 `(46+draw*22, 0)`，拉弦时弯得更开），中间一小段「弓弣」用三条短直线，弓弦 `lineTo` 到 `(-draw*46, 0)`（满弦时弦明显后移），再按 `draw>0.06` 画搭上的箭杆+镞。
- 配套：`Z.archer` / `Z.oldRider` 里 bow 的取点是 `x ± 52*s, y - 96*s`（马上是 `x ∓ 58*s, y - 104*s`）。**箭的起点必须落在这个弓口坐标上**，否则画面上会看到「箭从半空 / 从旗杆顶长出」。

### [人物] 同一个函数既要画青年又要画老年，必须开 `old` 开关
黄忠 h1（南阳，约 190 年）是三十出头，h2–h8 是白发老将。共用 `Z.archer/oldRider` 会全画成一张白盘子脸。
- `old:1` → 白盘子脸 + `Z.hairWhite`（盔下一撮白发）+ `Z.beard`（三笔白须垂胸）；`old:0` → 黑兜鍪 + 红缨。

### [审片] 射箭/砍杀这两类镜头，审片一定盯「动作有没有对象、箭从哪出来」
第一轮独立审片抓的六条，全是这类：
1. **定军山刀光砍的是自己马前腿**（刀光起点算错在马身上）→ 敌将放到 `520,900` 且放大，俯冲落点 `900,838`，刀光起点取人马之间的 `dx-150, dy-60`，朝左下敌将去。**高潮镜头必须先确认「被砍的东西画在那儿了」**。
2. **h2 的箭钉在敌旗杆顶上，像从旗杆长出** → 箭必须 `shot = ss(1.3,1.95,lt)` 从弓口飞向旗面，中间有飞行段。
3. **h3 箭射到帆上就不动了**，停留期间像一根灰线 → 加 `(1 - ss(1.9,2.15,lt))` 让它飞到即隐。
4. **h4 马头压住红旗** → 旗终点 `lerp(-100,400,…)`，别让马跑到旗上。
5. **h7「满弦」画面上没箭** → 箭起点要真的回到弓（`bx=zx-58*s*0.95, by=zy-104*s*0.95`），飞向画外。
6. **h6 五虎之印被马挡住「张」、右旗旗杆穿过「黄」印框** → 五印 `820+i*210`，老将左移 `zx=560`，右旗 `1640→1560`。

### [Windows] 这两个坑不仅 `render.py` 有，`qa.py` 也得回修
- `socketserver.TCPServer` → `ThreadingTCPServer` + `request_queue_size=128`。
- launch 加 `--no-proxy-server`。
- 只改 `render.py` 会导致「渲染能出片、qa.py 却 Timeout 180s」，很容易误判成片子有问题。

### [审片] 「鸟不动 / 人不动」的根因：母题循环用了**全局时间 t**
`Z.geese(c, t, { x0: 2100, speed: 170 })` 是按全局 `t` 排位置的。前面七幕把 `t` 已经推到几十秒，`2100/170 ≈ 12.4s` 才绕一圈，轮到 h7 时鸟早飞出画面了 —— 审片看到的是「20s 之后连鸟都不动」，实际是**从来没进来过**。
- 凡是「全片循环母题」（雁、云、潮、灯），在某一幕里要重新按该幕相位排布（`(lt*a + t*b + i*相位) % 1` 自己算），别指望跨幕组件自动带进来。
- `Z.mist(c, t, …)` 是周期函数、安全；`Z.geese` 是按 `t` 单向推进的、不安全。

### [水墨/笔法] 成片里绝不能出现 `setLineDash` 虚线
h5 法正「指向谷底」那一笔用了 `setLineDash([10,16])` + 红色，审片直接判为「没清理干净的动画引导线」。
- 改成细墨实弧（`rgba(58,48,38,.42)` / `lineWidth 2.4`），语义靠弧度和笔力表达，不靠虚线。
- 顺带：这类「辅助图形」的退场要提前（`ss(2.4,2.9)` 而非 `ss(2.9,3.4)`），高潮结束后别把引导线留在画面上。

### [造型] `flip` 决定弓在哪儿，飞行箭的起点必须跟着走
`Z.oldRider` 里 bow 的取点是 `x - 58*s*(flip ? 1 : -1)`：
- `flip:0` → 弓在 `x + 58*s`（身前右侧，人物朝右）
- `flip:1` → 弓在 `x - 58*s`（身前左侧，人物朝左，且 bow 内部 `scale(-s,s)` 把弓镜像朝左）
h2 里老将要迎击左侧来敌却没传 `flip`，弓画在右后方、箭却从左侧飞出 —— 审片一眼看出「箭和弓完全不相连」。
- 改法：马和人都传 `flip:1` 保持一致，箭的起点沿用 `x - 58*s, y - 104*s` 就正好落在弓上。
- 同理 h7 老将朝右（箭飞画外），保持 `flip:0`，起点 `x - 58*s*0.95` 是错的、应该是 `+58*s` —— **朝右射就别再取减号**。

### [ffmpeg] concat 清单必须用**相对文件名**，且 cwd 就在片元目录
这台机器上写 `file '/abs/path/s0.mp4'`（Windows 绝对路径）或直接 `-i _片元h2/list.txt`（相对上层目录），ffmpeg 一律 `Error opening input: No such file or directory`（它还会把相对路径拼成 `list所在目录/_片元h2/s0.mp4`）。
- 唯一能成的写法：`cd _片元h2` 后写 `file 's0.mp4'` …，`-i list.txt`，输出 `../成片.mp4`。

### [验收] 「静止帧对」才是死画面的硬指标，别只看运动%
`qa.py` 里 `运动 0.26% / 静止 0%` 看着很健康，但审片在 h7 判了「整幕 2.78 秒零动作」—— 因为「运动%」是按像素变化算的，轻微波浪/呼吸也会被算成运动。
- 真正要盯的是「静止帧对」那一列：黄忠定稿前 h6 是 17.1%（约半秒完全相同的相邻帧对），审片实测是 15.75–18.18s 持续 2.43 秒近乎静图。
- 修法不是加动画，是**加持续循环的活气**：殿前一缕青烟、阶下余尘、放箭后的马蹄扬尘、人物随 `sin(t*2)` 的呼吸微动。

### [验收] 黄忠 qa 基线（修复后应把它打到 0%）
- h6 修复前「静止帧对」17.1%（五印落定 + 老将接印那两秒画面几乎不动），其余幕 0%。改完重跑应全 0。
- 跳变：h1 冷启动 31 条（首帧一次性铺纸/远山），其余幕 0，属正常。
- 确定性全 ✓，无页面报错。
